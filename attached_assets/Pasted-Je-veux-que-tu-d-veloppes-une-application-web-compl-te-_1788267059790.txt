responsive et déployable en ligne dans le cadre d'un projet universitaire
de sécurité réseau.

==================================================
1. INFORMATIONS DU PROJET
==================================================

Titre :
PLATEFORME DE SENSIBILISATION AU PHISHING

Groupe :
GROUPE 17 – GOUVERNANCE DE SÉCURITÉ

Membres :
- BAMBULA THSIAKA-NJILA GODWINE
- MEKA KUMA PROSPER
- MOINDO ASOMBE MOISE
- NYAMASHI KUMAKAMBA MARTINE

Description :
L'objectif est de concevoir une plateforme web pédagogique permettant
de sensibiliser les utilisateurs aux risques liés au phishing à travers
des campagnes de phishing simulées, des quiz, un système de score,
des recommandations et des statistiques.

IMPORTANT :
Cette application est exclusivement pédagogique.
Elle ne doit jamais collecter de vrais mots de passe ou de données
bancaires et ne doit jamais être utilisée pour envoyer de véritables
campagnes malveillantes.

Toutes les données utilisées pour les simulations doivent être
fictives, synthétiques ou anonymisées.

dans le code source.

==================================================
6. CAMPAGNES DE PHISHING SIMULÉES
==================================================

Créer une section "Campagnes".

Créer plusieurs scénarios fictifs.

Exemples :

Campagne 1 :
"Vérification urgente de votre compte"

Campagne 2 :
"Notification de sécurité"

Campagne 3 :
"Réinitialisation de mot de passe"

Campagne 4 :
"Message de livraison"

Campagne 5 :
"Fausse récompense"

IMPORTANT :
Les scénarios doivent être clairement pédagogiques et fictifs.

NE PAS demander à l'utilisateur de saisir :

- véritable mot de passe ;
- numéro de carte bancaire ;
- code bancaire ;
- informations personnelles sensibles.

L'utilisateur doit uniquement analyser le scénario.

Pour chaque campagne, présenter :

- expéditeur fictif ;
- objet ;
- contenu du message ;
- lien fictif non dangereux ;
- indices suspects.

Demander :

"Ce message est-il légitime ou constitue-t-il une tentative de phishing ?"

Choix :

- Légitime
- Phishing

Après la réponse, afficher une explication pédagogique.

==================================================
7. QUIZ
==================================================

Créer une section "Quiz de sensibilisation".

Créer au minimum 10 questions.

Chaque question doit avoir plusieurs choix.

Exemples :

1. Quel élément peut indiquer un phishing ?
2. Pourquoi faut-il vérifier l'adresse de l'expéditeur ?
3. Que faire lorsqu'un message demande une action urgente ?
4. Pourquoi faut-il vérifier un lien avant de cliquer ?
5. Peut-on faire confiance à un message uniquement parce qu'il
   contient le logo d'une organisation ?
6. Que faire lorsqu'une pièce jointe paraît suspecte ?
7. Qu'est-ce que l'ingénierie sociale ?
8. Pourquoi utiliser l'authentification multifacteur ?
9. Comment signaler un message suspect ?
10. Quelle est la meilleure réaction face à un message douteux ?

Afficher une question à la fois.

Permettre de passer à la question suivante.

À la fin :

Calculer automatiquement le score.

==================================================
8. SYSTÈME DE SCORE
==================================================

Le score doit être calculé sur 100.

Exemple :

10 questions
8 bonnes réponses

Score = 80/100

Afficher :

- score ;
- nombre de bonnes réponses ;
- nombre de mauvaises réponses ;
- pourcentage ;
- niveau.

Utiliser les niveaux suivants :

0–39 :
"Faible"

40–59 :
"Moyen"

60–79 :
"Bon"

80–100 :
"Très bon"

Afficher une explication adaptée au niveau obtenu.

==================================================
9. RECOMMANDATIONS
==================================================

Créer un système de recommandations personnalisées.

Pour un score faible :

"Votre niveau de sensibilisation est faible.
Renforcez votre vigilance face aux liens suspects,
aux pièces jointes inconnues et aux demandes urgentes."

Pour un score moyen :

"Votre niveau est moyen.
Apprenez à vérifier systématiquement l'expéditeur,
les liens et le contexte du message."

Pour un bon score :

"Bon niveau de sensibilisation.
Continuez à appliquer les bonnes pratiques de sécurité."

Pour un très bon score :

"Excellent niveau.
Continuez à vérifier les expéditeurs, les liens et
les demandes inhabituelles."

Les recommandations doivent être stockées dans Firebase.

==================================================
11. AUTHENTIFICATION MULTIFACTEUR (MFA)
==================================================

L'accès administrateur doit utiliser une authentification multifacteur.

Processus :

Étape 1 :
Email + mot de passe

Étape 2 :
Second facteur

Étape 3 :
Accès au tableau de bord administrateur

Ne jamais afficher ou stocker le véritable code MFA.

Prévoir une configuration compatible avec Firebase Authentication
et ses mécanismes MFA.

==================================================
12. GESTION DES RÔLES
==================================================

Créer deux rôles :

"user"
"admin"

Un utilisateur possède le rôle :

"user"

Un administrateur possède le rôle :

"admin"

Les autorisations doivent être vérifiées côté serveur / Firebase
Security Rules et pas uniquement dans l'interface.

IMPORTANT :
Cacher simplement le bouton "Admin" ne constitue PAS une mesure
de sécurité suffisante.

Un utilisateur normal qui tente d'accéder directement à une
ressource administrative doit recevoir un refus d'accès.

==================================================
13. CONFIDENTIALITÉ DES RÉSULTATS
==================================================

Un utilisateur doit uniquement pouvoir consulter ses propres résultats.

L'utilisateur A ne doit jamais pouvoir consulter le résultat
de l'utilisateur B.

Les statistiques générales peuvent être affichées sous forme
anonymisée.

Exemple :

"72 % des participants ont obtenu un score supérieur à 70/100."

Ne pas afficher publiquement :

"Jean Dupont : 72/100"

15. FIREBASE SECURITY RULES
==================================================

Créer des règles de sécurité permettant notamment :

- utilisateur authentifié → accès aux fonctionnalités utilisateur ;
- utilisateur → lecture de ses propres résultats uniquement ;
- utilisateur → impossible de modifier son rôle ;
- utilisateur → impossible d'accéder aux données administratives ;
- administrateur → accès aux fonctions administratives autorisées ;
- empêcher les utilisateurs non authentifiés d'accéder aux données
  protégées.

Les règles doivent être réellement configurées et pas seulement
commentées dans le code.
